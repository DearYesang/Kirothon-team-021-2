05 · Kiro로 만든 방법

규칙 → 설계 → 병렬 구현 → 자동 검증

1

Steering

규칙을 먼저 고정

  • product.md 대상·가치·범위
  • tech.md 빌드·의존성·네트워크 없음
  • structure.md 파일 담당
  • tone-guide.md 관계별 말투
2

Spec

요구사항 → 설계 → 작업

  • requirements.md 사용자 스토리·인수 조건
  • design.md 엔진 API 계약을 먼저
  • tasks.md 엔진·UI·문서 작업
3

Hooks 4개

저장할 때마다 자동 확인

  • 엔진 코드 저장 → npm test
  • README 기능표·코드 위치 동기화
  • 비밀정보(API 키·.env) 검사
  • 톤 가이드 ↔ tone.js
4

서브에이전트 3개

파일 담당을 나눠 병렬 개발

  • 엔진: src/engine, 테스트
  • UI: index.html, src/app.js
  • 문서: README, BUILD_REPORT, 발표 자료
5

검증·배포

작동을 눈으로 확인

  • node:test 단위 테스트 (샘플 4종, 기준일 고정)
  • headless Edge 스크린샷·PDF
  • GitHub CLI: 레포 생성, PR, Pages 배포
바뀐 점 · Gemini API → 브라우저 안 규칙 엔진. 공개 레포에 키를 둘 수 없고, 심사위원이 키 없이 바로 열어야 하며, 메일이 브라우저 밖으로 나가면 안 되기 때문입니다.
